# Paper Trail — Fake News Detection Platform

Multi-model fake news detection with an agentic LangGraph verification pipeline,
article persistence, JWT auth, and region-aware evidence retrieval.

## Quick start

### 1. Install dependencies

```bash
pip install -r requirements.txt
```

`torch`, `transformers` and `sentence-transformers` are required, not optional —
claim verification runs a real NLI model and evidence relevance gating uses
sentence embeddings. Install torch for your platform first
(https://pytorch.org/get-started/locally/); the CUDA build is strongly
preferred. Without them the pipeline still runs, but it degrades to word-overlap
matching, says so in the response, and refuses to commit to a verdict.

The NLI model (~370 MB) downloads on first use.

### 2. Configure environment

```bash
cp .env.example .env
```

No API keys are required. Claim extraction is fully local, and evidence
retrieval works against Wikipedia without a key. Setting `NEWS_API_KEY`
additionally searches trusted news outlets (newsapi.org's free tier: 100
requests/day, English, ~1-month window).

### 3. Train models (run once)

```bash
python export_models.py            # full training (~10–30 min)
python export_models.py --skip-dl  # skip deep-learning models (faster)
```

Generates `models/registry.json`, `.joblib`/`.keras` artefacts, `results/all_results.csv`.

### 4. Start the API

```bash
uvicorn api.main:app --reload
# → http://localhost:8000
# → http://localhost:8000/docs  (Swagger UI)
```

### 5. Start the frontend

```bash
cd frontend && npm install && npm run dev
# → http://localhost:3000
```

## Run with Docker

Needs Docker with Compose. Runs the API (`:8000`) and the Next.js UI (`:3000`).

```bash
cp .env.example .env        # then fill in API keys and JWT_SECRET_KEY
docker compose up --build
```

- First start downloads the NLI/embedding models from Hugging Face (cached in a volume).
- The SQLite DB, evidence cache and model cache persist in named volumes.
- The browser calls the API, so if the API is not at `http://localhost:8000`, set
  `NEXT_PUBLIC_API_URL` in `.env` before building.
- NVIDIA GPU: `TORCH_INDEX=https://download.pytorch.org/whl/cu121 docker compose -f docker-compose.yml -f docker-compose.gpu.yml up --build`

### Paper Trail features

- **Check a link:** paste a news URL (or send `{"url": ...}`) and the server fetches the page
  (`api/url_fetch.py`, with `trafilatura` when installed), then verifies the article. Only public
  http(s) hosts are fetched; private/loopback/metadata addresses are refused on every redirect.
- **Linked sources:** each evidence snippet links to its article, with the outlet, publish date and
  a trust dot (green / amber / grey).
- **Claim highlighting:** each extracted claim is underlined in the checked text in its verdict
  colour; click one to jump to its evidence.
- **Shareable verdicts:** "Share" creates a public `/v/<slug>` page with a generated preview image
  for WhatsApp/X/Slack. "Stop sharing" revokes it. Set `NEXT_PUBLIC_SITE_URL` (and, in Docker,
  `API_INTERNAL_URL`) on the frontend so preview links are absolute.
- **Feedback:** 👍/👎 per verdict (signed in). A 👎 records a reason and comment in the `feedback`
  table, with the verdict at the time, as labelled data for re-fitting the fusion model.
- **Chat continuity:** after a check, keep talking in the same chat. Ask about a finding, push back
  on it ("but I read it was 1887"), or ask for a verdict. "Discuss" on any claim or verdict focuses
  the next message on that finding. Replies draw on every check and earlier message in the chat,
  citing evidence as `[n]`. When you state or ask about something the evidence doesn't cover, the
  assistant runs a new check through the full pipeline (`verify_claim` tool, max 2 per reply). That
  check shows inline, can be shared and rated, and becomes evidence for later messages.
  - With `ANTHROPIC_API_KEY` set, replies come from `QA_MODEL` (default `claude-opus-5-5`) using
    tool use (`api/chat.py`).
  - Without a key, a rule-based fallback still routes statements to new checks (turning "it was…"
    into a self-contained claim about the finding), answers verdict requests, and quotes the most
    relevant evidence.
  - The composer routes automatically: articles, links and images start a new check, and short
    messages go to the assistant. A hint above the box shows which will happen, with a one-click
    switch.

### Accounts and the free check

- **Test account:** `testuser` (or `test@dailytruth.app`) / `Test@1234` — seeded on startup
  (`SEED_TEST_USER=true`). `admin`/`admin123` and `analyst`/`analyst123` are seeded too.
- **One free check:** signed-out visitors can run `GUEST_QUERY_LIMIT` (default 1) checks on
  Paper Trail, counted per client IP. After that the API answers 401 with
  `detail.code = "guest_limit_reached"` and the UI shows a sign-in prompt. On sign-in the free
  check is moved into the user's history so the thread continues.
- **Previous chats:** every signed-in check belongs to a conversation, listed in the sidebar on
  `/verify` and reopenable at `/verify?c=<id>`. Owned checks are private to their owner.
- **Google sign-in (not configured yet):** create an OAuth 2.0 *Web* client in Google Cloud
  Console, add `http://localhost:3000` to its authorised JavaScript origins, then set
  `GOOGLE_CLIENT_ID=<id>` in `.env` and `NEXT_PUBLIC_GOOGLE_CLIENT_ID=<id>` in
  `frontend/.env.local`, and `pip install google-auth`. Until then the button says it isn't set up.

## Agentic pipeline

LangGraph StateGraph, entered via a conditional route on `input_type` — image
submissions pass through OCR first, text/URL submissions go straight to
language ID + translation:

```
(image) → ocr ─┐
                ├─→ translate → extract_claims → retrieve_evidence → verify_claims → run_ensemble → adjudicate
      (text) ───┘
```

A failed/low-confidence OCR read, or an untranslated/unsupported-language
submission, does **not** flow into the normal claims/ensemble/fusion path —
both route to a dedicated `abstain` node instead. See `_abstain_node`'s
docstring in `paper_trail_core/agents/pipeline.py` for why: with no real
English article text, that path let the trained fusion model score an
all-zero evidence vector it was never fit on.

| Node | What it does | Backend flag |
|------|--------------|--------------|
| `ocr` | Extracts text from an image (Tesseract + Hindi/English), confidence-gated | `OCR_BACKEND` (`tesseract`) |
| `translate` | Detects language; translates Hindi → English (English passes through untouched) | `TRANSLATION_BACKEND` (`llm`) |
| `extract_claims` | Segments sentences, ranks by check-worthiness | `CLAIM_BACKEND` (`heuristic`) |
| `retrieve_evidence` | Entity queries → NewsAPI + Wikipedia, relevance-gated, cached | `EVIDENCE_BACKEND` (`live`) |
| `verify_claims` | NLI over (evidence sentence, claim) pairs | `NLI_BACKEND` (`transformer`) |
| `run_ensemble` | Stacking ensemble P(real) — one feature, not the verdict | `ENSEMBLE_BACKEND` (`real`) |
| `adjudicate` | Calibrated fusion → verdict or abstention | — |

`ocr` requires the Tesseract system binary plus the Hindi (`hin`) language
pack, installed separately — see `requirements.txt`. Without it, image
submissions degrade to the abstain path rather than guessing. `translate`
supports English (pass-through) and Hindi (via the Anthropic gateway) only
for now — any other detected language also abstains rather than running
English-tuned models on text they weren't built for.

Each stage names its own backend. The old single `MOCK_MODE` flag gated two
unrelated stages at once and defaulted to on, so the pipeline silently ran
word-overlap matching in place of NLI. Setting `MOCK_MODE=true` still works and
maps onto the degraded backends, but it is deprecated and the pipeline will
report it as a critical degradation.

**Abstention:** when the fused score falls inside the abstention band — or when
NLI ran degraded, or no claim could be checked at all — the verdict is
`uncertain`, with the reason in `reasoning_trace` and `degradations`. There is
no human-review step: the pipeline always returns an answer on its own. Band
edges are chosen on held-out data to hold a target precision.

**Region-aware verification.** After claims are extracted, the `locate` stage
works out where each claim is about — as precisely as the text supports, from a
street or landmark up to a country — and the evidence stage then searches
regional news for that place *in addition to* the usual global sources. See
[docs/VERIFICATION_PIPELINE.md](docs/VERIFICATION_PIPELINE.md#stage-1b--locating-claims-region-aware).

**Claim mode.** One or two sentences (up to 300 characters) are treated as a
*claim* rather than an article: the verdict is decided on evidence alone
(supported → `likely_real`, refuted → `likely_fake`, otherwise `uncertain`),
because the style classifier and fusion model were fitted on whole articles and
are unreliable on a single sentence. Compound claims are split, each named
subject is looked up directly, and only a page about the claim's own subject may
refute it. Longer text takes the unchanged article path; `CLAIM_MODE=false`
disables this. Measured results and their limits are in
[docs/VERIFICATION_PIPELINE.md](docs/VERIFICATION_PIPELINE.md#claim-mode--one-or-two-sentences).

**Submission is asynchronous.** `POST /articles/submit` returns **202** with
`status="processing"`; poll `GET /articles/{id}` until `completed` or `failed`.

Full detail, including the measured limitations, is in
[docs/VERIFICATION_PIPELINE.md](docs/VERIFICATION_PIPELINE.md).

### Evaluating it

```bash
py scripts/evaluate_pipeline.py --slice golden                    # novel articles
py scripts/evaluate_pipeline.py --slice holdout --n-per-class 150 # leak-free split
py scripts/train_fusion.py --input results/eval_per_article_holdout.csv
```

Reports land in `results/` with accuracy, per-class precision/recall,
calibration (ECE), a coverage-vs-precision curve, and an
ensemble-only / evidence-only / fused ablation.

## Tests

```bash
pytest tests/ -v
```

107 tests, all offline: retrieval is monkeypatched, NLI is stubbed, and the API
tests mock the pipeline, so no trained models, GPU or API keys are required.

Notable regression coverage:

- `test_claim_extractor.py` — decimals must not be split (`6.75 percent` stays
  one claim), and the preserved `naive` backend must still reproduce the bug so
  the assertion cannot pass vacuously.
- `test_verifier.py` — NLI labels are read from config, not position (the two
  checkpoints used here order them inversely); a confident `neutral` must not
  beat an `entailment`; absence of evidence must never yield `contradiction`.
- `test_adjudicator.py` — degraded NLI and zero coverage both force abstention.
- `test_pipeline_e2e.py` — the exact JSON contract the frontend dereferences
  without null checks, including under total stage failure.

## Database schema (for cross-team joins)

```

              ensemble_score, reasoning_trace, degradations JSON, fused_score,
```

`claim_verdicts` JSON includes each claim's `location` when one was found. The
`review_queue` table and the `verdicts.needs_human_review` column were removed
